# Data model: node and process usage

All persisted timestamps are UTC instants; wire times are ISO 8601 UTC with `Z`. Raw memory is bytes, CPU/device utilization is a percentage of the stated scope (0–100), temperature is °C, power is W. The UI converts memory to one-decimal GiB. See [contracts/usage-monitor.md](contracts/usage-monitor.md) for wire format.

| Entity | Fields | Relationships / validation |
| --- | --- | --- |
| Node | `node_id` (stable key), display host, `role` (master/worker), backend/devices and reported capacity, last contact, membership state, known assignment | `node_id` is saved in `ClusterState`. Display host is not a key. Membership comes from master status; departed node metadata persists only while associated retained history is needed. A rejoin with the same ID updates a single live card. |
| Cluster relationship | `from_node_id`, `to_node_id`, kind (`master-worker`), observed membership state | Only registered master→worker links. Lines express known cluster membership, never measured traffic, physical adjacency or a worker→worker link. |
| Managed process lifetime | `lifetime_id` (derived from `node_id`, PID and actual process creation UTC time), node ID, PID, role, creation time, observed last sample/end time, state (`running`, `ended`, `unobserved`), time-bounded known workload/model associations | PID must be tracked by the local agent; never enumerate unrelated processes. Agent restart reads actual start identity and continues the same lifetime. Exit or PID reuse closes the old observed lifetime; no subsequent samples attach to it. Worker lifetime need not change when its model association changes. |
| Usage reading | lifetime ID, node ID, observed/received UTC timestamps, process CPU % machine, process RSS bytes, host CPU % and used/total physical bytes, optional per-device values, per-field availability/reason, optional collector error | Unique `(lifetime_id, observed_at)` for an accepted process sample; scopes are `process`, `host`, `device`. Non-finite/negative/out-of-range values and mismatched node/PID/creation identity are invalid, not zero. Unsupported metrics are `null` with availability reason. Late valid data can appear in history without replacing the latest observation. No prompts, responses, credentials, command lines, or unrelated processes. |
| Recording coverage | window start/end, earliest/latest retained observation, `last_successful_save`, `recording` / `interrupted` / `failed`, error when known, `storage_truncated`, gap intervals | Master-local status and retained metadata support history when a browser closes, an agent restarts, a node departs, or a write fails. Empty history before monitoring began is `unrecorded`. Missing intervals remain gaps; gaps are not readings with zero values. Entire cluster has a rolling 24-hour window and one 256 MiB physical budget including SQLite sidecars. |

## State transitions

1. A tracked child is observed → validate PID and `create_time`, open/reuse its lifetime, prime CPU measurement (unavailable until a delta exists), begin two-second sampling. No tracked child → `no managed process` rather than CPU zero. Agent restart observing the same process continues its lifetime.
2. Fresh accepted reading → commit transaction within ten seconds in a healthy recorder and advance that lifetime's live reading only if newer. At ten seconds without fresh measurement, show last reading **stale** with time/age; never show it as fresh or idle.
3. Process exits or new start identity replaces the PID → mark the old lifetime ended at the last observed boundary, then start a new one if present. The unobserved gap is not assigned invented usage. Assignment/activity change updates contextual associations without forcing worker process restart.
4. Node contact ends → master marks it disconnected within 25 seconds of last contact and removes it from live membership according to the existing sweep; retained node/lifetimes remain selectable until their readings and coverage age out. Rejoining the same ID restores connected state, not a duplicate card.
5. An observation fails or transport disconnects → show explicit unavailable/interrupt state and gap. Malformed/duplicate observations are rejected; a valid late reading may enter history but cannot replace newer live values. Out-of-sync clocks must not reorder live by receive order; timestamps outside the accepted skew range are rejected with a diagnostic.
6. Retention ages or physical budget is reached → retire oldest readings first, reclaim actual file space, retain enough identity to interpret remaining points, expose the new earliest time and `storage_truncated` when storage shortened the 24-hour interval. Failed saves/reads expose last successful save/error; previously committed data remains readable where the store is healthy.

## Presentation invariants

- Process CPU uses whole-machine logical capacity; host CPU and per-device utilization never share an unlabeled percentage. Measured process RSS, measured host RAM, measured device-wide RAM, device capacity and planned allocation remain distinct.
- Shared/unified memory is one physical pool, labeled `shared`; do not sum host and shared-device values. If a combined measured total lacks any required component, label it partial rather than inventing completeness.
- Assignment means planned work; `inference_activity` means master-observed cluster phase; neither proves locally measured device work. `unsupported`, `collection error`, `stale`, `disconnected`, `unrecorded` and `measured zero` are distinct textual states.
